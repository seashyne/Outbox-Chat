# 2026-11-14

## Outbox Chat (Discord-like clone in Rust) — completed

- Built a full working Discord-style realtime chat in workspace `Outbox Project 1x`.
- Stack decision: axum 0.8 + tokio 1 + tower-http (ServeDir/CORS) + serde/serde_json + uuid v4 + chrono; no SQL, no native deps. Data persisted as `data/store.json` via temp-file + atomic rename.
- Structure: `src/{main,model,state,error,handlers,ws}.rs`, `web/{index.html,style.css,app.js,favicon.svg}`, `README.md`, `Cargo.toml`.
- Features: register (bearer token), bootstrap, servers directory/join/create, text+voice channels, message history/post/delete, role-based delete (owner/admin), typing, presence (multi-tab counted), voice presence, membership-filtered WebSocket fan-out, heartbeat, reconnect, light/dark theme.
- Important design choice: voice_join requires a live WebSocket connection, otherwise REST-only joins leave ghost participants. Documented in README.
- Verification: `cargo fmt --check`, `cargo test` (3 tests pass), `cargo build`, curl REST smoke tests (auth 401, 404, 409, 400, 204), Node WebSocket end-to-end (ready/presence/typing/message_create/voice_state/membership leak = none), headless Chrome CDP UI test (login, send, create server, voice join, theme toggle) — zero JS errors.
- Test data was cleared; DB reseeds to `Outbox HQ` demo server on first launch. Server runs on port 3000 (`cargo run`, env `PORT`/`WEB_DIR`/`DATA_PATH`).
- Known limits (documented in README roadmap): no real audio (WebRTC), no password/OAuth, single JSON file store, no rate limit/TLS — demo/learning only.
